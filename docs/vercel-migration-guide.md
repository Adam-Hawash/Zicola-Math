# خطة نقل منصة Zicola In Math إلى Vercel — نشر موازي صفر قطع

**القرار**: نفس الرابط `zicola-in-math.com` يشتغل من فيرسل بدل بنية كلاود فلير المضطربة في الشرق الأوسط — نفس المحتوى بالحرف، نفس قاعدة البيانات، نفس الحسابات، **بدون أي طريق بديل للطلاب**.

**ليه فيرسل تحديداً**: المنصتين الشريكتين (صبري وشريف) شغالين عليه عندك بنفس اللوحة اللي تعرفها. وقاعدة البيانات Turso بتتشاف من فيرسل مباشرة عبر HTTP — فالدروس والورقات والرسومات والحسابات هتفضل نفسها بالحرف لأنها كلها مخزنة في نفس القاعدة (جدول Media base64 — متأكد من الكود).

**ليه آمن 100%**: بننشر نسخة موازية على لينك مؤقت فيرسل ونختبرها كاملة أولاً. لحظة تبديل الدومين لو حصلت أي حاجة بنرجع في أقل من دقيقة. المنصة القديمة طول فترة النقل شغالة زي ما هي.

---

## الخطوة 1: القيمتان من لوحة كلاود فلير (نسخ ولصق فقط)

1. افتح dash.cloudflare.com → **Workers & Pages** → **zicola-math**
2. **Settings** → **Variables and Secrets**
3. انسخ قيمتين كما هما بالحرف:
   - `TURSO_DATABASE_URL` (شكلها `libsql://...`)
   - `TURSO_AUTH_TOKEN` (سلسلة طويلة)
4. لو القيمة مخفية اضغط علامة العين (Reveal) لتظهر

## الخطوة 2: الرفع على فيرسل (نفس تجربة صبري وشريف)

1. vercel.com → سجل دخول بـ GitHub (نفس حساب Adam-Hawash)
2. **Add New** → **Project** → ابحث **Zicola-Math** → **Import**
3. Framework Preset هيكتشف **Next.js** تلقائياً — ما تغيرش Build Command ولا Output
4. قبل الضغط على Deploy: افتح قسم **Environment Variables** وأضف السطرين:
   - `TURSO_DATABASE_URL` = القيمة من الخطوة 1
   - `TURSO_AUTH_TOKEN` = القيمة من الخطوة 1
5. **Deploy** — يستغرق 3-5 دقائق
6. افتح لينك المعاينة (`something.vercel.app`) — المنصة لازم تفتح بنفس شكلها

## الخطوة 3: الاختبار قبل لمس الدومين

ابعت لي لينك المعاينة وأنا أختبر كل شيء حياً (الصفحات + تسجيل الدخول + درس كامل + معرض + الرفع) — أو اختبر بنفسك: الرئيسية، تسجيل دخول أدمن، فتح درس، معرض الصور.

## الخطوة 4: تبديل الدومين (بعد نجاح الاختبار فقط)

**في لوحة فيرسل**: المشروع → **Settings** → **Domains** → **Add** → اكتب `zicola-in-math.com` — فيرسل هيقولك حط CNAME على `cname.vercel-dns.com`

**في لوحة كلاود فلير**: **DNS** → **Records** → سجل الدومين الحالي → **Edit**:
- النوع: `CNAME`
- الهدف: `cname.vercel-dns.com`
- **أطفأ البروكسي** (السحابة البرتقالية تبقى رمادية — DNS only)
- **Save**

- بعد دقائق فيرسل بيصدر شهادة SSL أوتوماتيك وبتتجدد لوحدها
- تحويل http→https شغال تلقائي + middleware ر14/HSTS موجود في الكود زي ما هو
- **التراجع فوري**: رجّع السجل لقيمته القديمة → المنصة القديمة ترجع شغالة في دقيقة

## ملحق تقني: ليه المشروع جاهز للفيرسل من غير تعديل سطر واحد

| الفحص | النتيجة |
|---|---|
| بناء Next.js قياسي (بناء فيرسل بالحرف) | **ناجح EXIT=0** — `prisma generate && next build` |
| قاعدة البيانات | Prisma + adapter-libsql يقرا `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` من البيئة — تشتغل من فيرسل مباشرة |
| الرفع والملفات | كلها base64 في جدول Media بالتورسو — مفيش R2 ولا قرص محلي |
| proxy.ts (HTTPS + HSTS) | middleware قياسي يقرا `x-forwarded-proto` — موجود في فيرسل |
| instrumentation.ts | register فاضي آمن على أي runtime |
| إعدادات القص السيرفري | `serverExternalPackages` + `outputFileTracingIncludes` معدة أصلاً بتعليقات Vercel (و49/و50) |
| cron الإحماء | مش لازمة — مشيت مع المنصتين الشريكتين بنفس الوضع |

## ملحق: ليه فيرسل بيحل مشكلة مصر

المسار القديم: الطالب في مصر → بنية كلاود فلير الإقليمية (**معلنة رسمياً under_maintenance** على صفحة حالتها) → المنصة.
المسار الجديد: الطالب في مصر → مركز فيرسل (نفس بنية صبري وشريف اللي شغالين عندهم في مصر) → المنصة.
يعني المشكلة بتتقفل من جذرها — مش بنعتمد على إصلاح كلاود فلير ولا على حيلة ولا على طريق بديل.
